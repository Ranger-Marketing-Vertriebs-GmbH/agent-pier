> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move AgentPier's managed OpenClaw runtime from 2026.10.3 to 2026.10.7 (AGENTPIER-196), qualified on every update path, shipping as AgentPier 2.7.0.

**Architecture:** A spike against the real 10.7 package settles the two unknowns first (agent DB schema 24 → 25 on a plain Gateway start, and the shape of the new exec-completion turn). Then the manifest and lock move, the exec-continuation proof learns the new completion turn while keeping the heartbeat proof for the rollback targets, an activation-time `openclaw doctor --fix` step is added only if the spike requires it, the version lists move after their contracts pass, CI gains the v2.6.1 predecessor, and the docs and release-note text record the qualification.

**Tech Stack:** Node.js ES modules, `node:test`, OpenClaw Gateway protocol v4, npm lock refresh scripts, GitHub Actions.

## Spec

Owner decisions (2026-10-24):

1. **Target OpenClaw 2026.10.7.** 2026.10.6 is the fallback only if 10.7 shows a blocker during qualification; the fallback changes pins only, not the adaptations.
2. **Release:** AgentPier 2.7.0 (the version bump itself is the separate version PR of the release workflow).
3. **One-way warning:** activation migrates each agent's OpenClaw database from schema 24 to 25. The release notes carry a "Before you update" warning in the style of 2.1.0's: snapshot rollback works before commit; after commit there is no return to OpenClaw 2026.10.3 or AgentPier 2.6.x and earlier.
4. **Background-command follow-ups keep working as today:** a completion turn of a background `exec` an owner turn started may still continue that owner turn's writes (memory, files, project folders), with the same proofs, limits and audit (`via: "exec-completion"`).
5. **Rollback targets before commit:** `["2026.10.3", "2026.9.9", "2026.9.8"]`, newest first. The team plugin stays compatible with each.

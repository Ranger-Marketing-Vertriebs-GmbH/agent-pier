# MCP OAuth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remote MCP servers in the central list can sign in with OAuth through OpenClaw's native MCP OAuth, driven from AgentPier with status, login and logout.

**Architecture:** A remote server record gains `auth: "headers" | "oauth"`. The compiler writes `auth: "oauth"` and `oauth: { redirectUrl, scope? }`, with the redirect on AgentPier's own origin. A small CLI wrapper runs `openclaw mcp login|status|logout` against the Gateway's private environment. A login service keeps pending logins keyed by `state`; the callback route checks `state` and completes with `--code`. Tokens stay in OpenClaw's SQLite.

**Tech Stack:** Node.js 22 ESM, `node:test`, React with DE/EN reactive catalogs, Playwright, OpenClaw 2026.9.8 CLI and Gateway.

**Spec:** `docs/superpowers/specs/2026-10-11-mcp-oauth-design.md`

## Global Constraints

- Default `auth: "headers"`; existing records keep working unchanged.
- Redirect: `<origin>/api/mcp-servers/oauth/callback`; origin = `config.remoteUrl` origin (HTTPS) when set, else the loopback address of the AgentPier listener. Plain-HTTP non-loopback access → login refused with a clear message before it starts.
- Pending logins expire after 10 minutes and are single use; the callback requires an authenticated owner session.
- The authorization code, tokens and CLI output containing them never reach logs, audit or browser responses.
- OAuth logins are not in backups; restore shows "Login required".
- Before rename, URL change, switch to headers, or delete of an OAuth server, AgentPier logs out under the old name and URL.
- Every UI text in German and English; 390 px usable; files ≤ 600 lines; English conventional commits with a `Co-Authored-By` trailer for the authoring model.
- Tests never touch the user's instance, `~/.openclaw`, port 4380, the default tmux server; never kill processes the test did not start.

## Review Focus

- The CLI's printed authorization URL format changes or the CLI unexpectedly binds a port: the wrapper must fail with a clear error, never hang — pinned in Tasks 1 and 4.
- A callback with a wrong, expired or reused `state` must not complete any login — pinned in Task 5.
- Renaming or changing the URL of a logged-in server must not leave an orphaned, still-valid login in OpenClaw — pinned in Tasks 1 and 5.
- An OAuth server without a valid login must not break agent turns; the agent simply lacks its tools — pinned in Task 1 and Task 8.
- The OpenClaw state directory must not leak OAuth tokens into AgentPier backups or runtime update snapshots — pinned in Task 6.

### Task 1: Qualify OpenClaw MCP OAuth live

**Files:** create `tests/helpers/mcp-oauth-test-server.js` (local mock authorization server: protected resource metadata, AS metadata, dynamic client registration, PKCE authorize with auto-approve redirect, token and refresh endpoints with short expiry; mock streamable-HTTP MCP server requiring the bearer token, one tool), `tests/integration/assistant-mcp-oauth-contract.test.js` (runtime variable `AGENTPIER_MCP_CONTRACT_RUNTIME`, existing provisioning), `docs/mcp-oauth-qualification.md`.

**Produces (verified facts for Tasks 3–8):**

- (a) `openclaw mcp login <name>` with the redirect port already taken: exact stdout/stderr shape of the printed authorization URL, exit code, duration; that it does not hang;
- (b) `openclaw mcp login <name> --code <code>` completes; exit code and output; the next agent turn lists `<name>__<tool>` without a config reload;
- (c) `openclaw mcp status --json` shape for `unauthenticated`, `pending-authorization`, `authorized` (with `expiresAt`), `requires-authorization`;
- (d) unattended refresh after expiry; revoked refresh token → `requires-authorization` and the agent turn still runs without the tools;
- (e) `openclaw mcp logout <name>` clears it; rename and URL change orphan the login (store key = hash of name and URL);
- (f) the environment the CLI needs to hit the Gateway's private state (HOME, `OPENCLAW_STATE_DIR`, config path) and whether it needs the Gateway running;
- (g) whether `oauth.redirectUrl` with an HTTPS origin that is not reachable locally still lets `login` print the URL.

- [ ] Steps: write the mock servers; write the contract driving a pinned Gateway with one OAuth server (redirect on a port the test holds open); record facts; run with the provisioned runtime; commit `test: qualify OpenClaw MCP OAuth against a mock authorization server`.

If (a) shows the CLI cannot print a URL without binding or blocking, STOP and report to the controller (design revisit).

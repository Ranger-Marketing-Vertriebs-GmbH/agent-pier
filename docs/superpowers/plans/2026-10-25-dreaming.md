# Switchable OpenClaw Dreaming Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One global owner switch (with a sweep hour) that turns on OpenClaw memory-core's nightly dreaming for every permanent agent, turns memory on for all of them first, and keeps it on while dreaming runs.

**Architecture:** A small settings store (`dreaming-settings.js`, own SQLite like `pdf-model.sqlite`) feeds the memory-core `dreaming` section that `compileOpenClawConfig` writes, and a live `config.patch` applies changes without a restart. A `DreamingService` owns the switch: it lists permanent agents without memory, raises their memory after the owner's confirmation and only then stores `enabled`. The assistant service refuses switching memory off while dreaming is on; new permanent agents start with memory on. A `DreamingSweep` in AgentPier backs up each covered agent's `MEMORY.md` before the night's run, triggers the run per agent itself when memory-core cannot leave temporary members out, and removes a deleted chat from dreaming's copies. The memory view lists dream notes like any note and shows the Dream Diary read-only. Independently of the switch, a shared agent's pre-compaction flush and memory step write its shared memory, and the shared-agent chat notice says so.

**Tech Stack:** Node.js ES modules, Express, node:sqlite (`privateDatabase`), React/JSX, `node:test`, Playwright, OpenClaw 2026.10.7 (memory-core).

**Spec:** Plane ticket AGENTPIER-215, owner-approved design in its comments (no separate spec file). The binding points are copied into Global Constraints and "Design decisions" below; executors read both sections.

## Global Constraints

- Runtime pinned at OpenClaw `2026.10.7` (`server/features/assistants/runtime-manifest.js`); no runtime bump in this branch.
- One global switch; default sweep **03:00** in the owner's time zone; the hour is adjustable next to the switch.
- Covered: personal agents, permanent team members, restricted users' agents (own and shared) — each only its own conversations into its own memory. A shared agent dreams over all its chats (every user's and the owner's own) into its one shared memory; that is intended. Its raw corpus (`memory/.dreams/`) never becomes readable to its users or the owner: only the distilled notes are. Not covered: temporary (task-bound) members; nothing is ever written into `memory/lead/`.
- Each agent dreams with its own model and model account (its connection or ChatGPT account); there is no global dreaming model.
- Deep phase on; before each night's run AgentPier backs up every covered agent's `MEMORY.md` (last 7 kept, outside the workspace, never in the memory view or Git).
- Deleting a chat also removes its content from dreaming's copies (session corpus and per-session ingestion state). Notes already distilled from it stay, like any saved memory write.
- Switching on lists the permanent agents with "Remember information" off and, after the owner confirms, turns memory on for all of them. While dreaming is on, "Remember information" cannot be switched off for any permanent agent and the switch says why.
- New permanent agents have memory on by default, also while dreaming is off.
- A promoted member joins from the next night (no special handling beyond being in the sweep).
- Dream notes show in the agent's memory view like any note; the Dream Diary is readable there, never editable.
- No night is skipped for a busy agent: its sweep runs once no turn is running; running turns, open work goals (nudge in `work-goal-nudges.js`) and summaries continue afterwards.
- Independent of the switch: on a shared agent the pre-compaction flush and the memory step before **Summarise now** write its shared memory like a saved write (with the existing "shared-write" note in the writing chat only), and the shared-agent chat notice says that what is written there can be carried into the shared memory that all its users and the owner read.
- Contract fixtures use resolved temp paths (`fs.realpathSync(os.tmpdir())`); never target the real data dir or the default tmux server.
- Files checked by `check:structure` stay ≤ 600 lines. `server/features/assistants/assistant-service.js` (600) and `server/application/assistant-graph.js` (600) are at the cap and `team-store.js` is at 599: changes there must be net zero lines (move code into the new modules).
- Every UI string in `web/lib/i18n/de/` and `web/lib/i18n/en/` with matching keys and arguments, imported from `web/lib/i18n/messages/`; server messages in `server/lib/i18n/de/` and `server/lib/i18n/en/`; run `npm run i18n:confirm` and commit the `translation-lock.json` files.
- UI uses only `docs/ui-guide.md` components (`ToggleRow`, `SelectRow`, `ListCard`, `GroupLabel`, `Sheet`); no new colours, font sizes or breakpoints.
- Docs in English; commits `feat:`/`fix:`/`test:`/`docs:` imperative, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Do not push.

## Design decisions (plan-level, from the ticket and the code)

- **Trigger:** keep memory-core's own single managed cron (`memory-core:memory-dreaming-promotion`), with `frequency: "0 <hour> * * *"` and `timezone`, _if_ Task 1 confirms it runs outside AgentPier agents' sessions (a busy agent is swept "in between") **and** a per-agent lever keeps temporary members out. **Fallback (no such lever):** AgentPier triggers the sweep itself. memory-core stays enabled without its managed cron (the config Task 1 Step 3 pins), and `DreamingSweep` (Task 7) runs at the hour, for each covered agent in turn, the per-agent dreaming call Task 1 Step 3 identifies; an agent with a running turn is retried every minute until it is idle, the same night. If 10.7 offers neither a per-agent lever nor a per-agent call, Task 1 stops for re-plan.
- **Phases:** light, REM and **deep on**. Deep promotes into and may rewrite `MEMORY.md` (`maxPriorEntryLossFraction`), so `DreamingSweep` copies `MEMORY.md` to `assistants/memory-backups/<runtimeAgentId>/MEMORY-<UTC stamp>.md` in the data dir (`privateFolder`, mode 0600, last 7 kept) before each run: five minutes before the hour on the cron path, right before each agent's call on the fallback. Outside the workspace, so neither the agent's tools nor the memory view reach it. Storage `mode: "separate"` so dream notes land in their own files under `memory/` instead of appending to the agent's day note.
- **Model:** memory-core's light, REM, deep and diary calls use the swept agent's own model and connection; AgentPier compiles no dreaming model. Task 1 proves it; a global model is a stop.
- **Stored settings:** `{ revision, enabled, hour, timeZone }`, defaults `{ enabled: false, hour: 3, timeZone: "UTC" }`; the client sends the browser's zone when switching on (same pattern as check-ins, `ProactivityGroup.jsx` "adopt zone").
- **Covered agents:** `personalEligible(agent)` (`native-capabilities.js`): not archived, and not a team member or a permanent one. That includes users' agents.

## Review Focus

1. **Shared agents (restricted users, mode "shared"):** they dream over every user's and the owner's chat into the one shared memory, and their flush and memory step now write it (owner decision: distilled notes in shared memory are intended). Expected: user A's raw transcript never becomes verbatim readable to user B or the owner: `memory/.dreams/` never appears in the memory view and the agent's file tools refuse it (Task 5), `memory_search` returns no corpus text (Task 1, stop otherwise); a shared flush leaves "shared-write" only in the flushing chat, and the notice says it (Task 8).
2. **Agent busy at switch-on:** bulk memory-on hits `assistantProblem("active", 409)` for an agent in a running turn. Expected: the switch stays off, nothing is half-claimed, the owner sees which agents are busy and can retry; agents already raised keep memory. Test in Task 3.
3. **Memory-off attempts while dreaming is on** from every path: settings PATCH, a create with `memory: false`, a user agent created through `users/user-agents.js`. Expected: refused with the explanatory key, never silently ignored. Tests in Task 4.
4. **Hour / time zone edits while on:** changing the hour must move the cron job, not add a second one; switching off removes the job. Expected: exactly one `declarationKey === "memory-core:memory-dreaming-promotion"` job with the new expression, none after off. Test in Task 1 (live) and Task 2 (compile).
5. **Dream Diary as a path:** `DREAMS.md` read through the memory view must not follow a symlink, must refuse writes and deletes. Test in Task 5.
6. **Deep phase and `MEMORY.md`:** a backup exists before every run, at most 7 are kept, a missing or linked `MEMORY.md` is skipped, and the backups sit outside the workspace. Test in Task 7.
7. **Chat deletion:** a deleted chat (also a released or deleted user's) leaves no text and no ingestion entry in `memory/.dreams/`; other chats' corpus stays. Test in Task 7.
8. **Own model per agent, temporary members out:** Task 1 proves both on the runtime; on the fallback path Task 7 tests that only covered agents are called and a busy one is called once it is idle.
